# rke201v2-lab: Unattended VM Provisioning (AutoYaST)

This folder automates the parts of [../README.MD](../README.MD) that were still manual:
booting the openSUSE Leap 16.0 installer and clicking through it, then setting
hostname, static IP, user account, and SSH by hand inside each VM. The main
`README.MD` is left untouched and still documents the manual, learn-by-doing
path - use this folder when you just want the 3 VMs rebuilt quickly and
unattended.

## How it works

openSUSE's installer (YaST) supports **AutoYaST**: an XML answer file
(`autoinst.xml`) that drives the entire install non-interactively. Normally you
point the installer at it with a boot parameter, but that requires typing at
the boot menu - not exactly "unattended". Instead, this uses a documented
YaST feature: **a second CD/DVD volume labeled exactly `OEMDRV`, containing
`autoinst.xml` at its root, is auto-detected with no boot parameter at all.**

So each VM gets two virtual DVD drives:
1. The existing Leap 16.0 offline installer ISO (boot device, unchanged from the main README)
2. A small generated ISO labeled `OEMDRV` containing that VM's AutoYaST profile

The installer boots, finds the OEMDRV profile automatically, partitions the
disk(s), installs the OS, sets the hostname/static IP/user/SSH, runs a
post-install script, and reboots into a ready-to-SSH machine.

## Layout

```
automation/
├── autoyast/
│   ├── management.xml   # RKE201-management: 2 vCPU/2GB, 40GB+10GB disks, desktop pattern
│   ├── server.xml       # RKE201-server:      2 vCPU/6GB, 40GB disk, headless
│   └── agent.xml        # RKE201-agent:       2 vCPU/6GB, 40GB disk, headless
├── oemdrv-iso/           # generated by 01-build-oemdrv-isos.ps1 (git-ignored, not checked in)
└── scripts/
    ├── 01-build-oemdrv-isos.ps1     # builds the 3 OEMDRV ISOs from the profiles above
    ├── 02-create-vms-unattended.ps1 # creates the VMs and boots them into the unattended install
    └── 03-wait-for-ssh.ps1          # polls port 22 on all 3 IPs so you know when it's done
```

Each AutoYaST profile configures the same things the main README's Phase 0.0-0.3
walk through by hand:
- Partitioning (guided/automatic proposal; management additionally gets its
  second 10GB disk formatted ext4 and mounted at `/data/nfs-share` - actually
  exporting it over NFS is a later phase and is **not** automated here)
- Static IP, gateway, DNS (`8.8.8.8`/`8.8.4.4`, same as `../scripts/03-change-ip-address.sh`), hostname/FQDN
- Timezone `America/Detroit` (applied to all 3 VMs for consistency; the main README only states this for `server` today)
- The shared lab account (`tux` / `linux`, full name `Tux Penguins`, sudo via `wheel`) plus a `root` account with the same password
- OpenSSH installed and enabled
- The same `/etc/hosts` block as the main README, written on every VM
- SUSE registration skipped (offline install) and all interactive popups suppressed, so nothing can block waiting for input

**Note on the shared password:** `tux`/`linux` is already the published,
shared lab credential in the main README - embedding it in these profiles
doesn't introduce a new secret, it's the same one, and this is an isolated
lab network with no internet-facing exposure.

## Prerequisites

Run once, from the main lab (these are **not** duplicated here):
- `../README.MD` Phase 0.0 - hosts file entries on the Windows host
- `../scripts/00-create-network.ps1` - Hyper-V switch + NAT

## Usage

From an elevated PowerShell prompt on the Hyper-V host:

```ps1
cd automation\scripts

.\01-build-oemdrv-isos.ps1
.\02-create-vms-unattended.ps1
.\03-wait-for-ssh.ps1
```

`02-create-vms-unattended.ps1` is idempotent, like the main README's
`01-create-vms.ps1` - it skips any VM that already exists rather than
recreating or destroying it.

For the **first** run, keep a Hyper-V Manager console window open on one VM to
confirm the install proceeds with no manual prompts (partitioning, network,
account, and the post-install script all happen automatically). Full install
time depends on host resources; budget 15-30 minutes per VM.

## Verification

Once `03-wait-for-ssh.ps1` reports all 3 reachable:

```ps1
Get-VM

ssh tux@management
ssh tux@server
ssh tux@agent
```

On each VM, the same checks the main README documents should now already pass:
```bash
hostnamectl
cat /etc/hosts
ip address show
systemctl status sshd
```

## Troubleshooting / things to double-check on first run

- **Disk device names**: profiles assume `/dev/sda` (and `/dev/sdb` for
  management's second disk), which is standard for Hyper-V Gen2 synthetic
  SCSI disks under Linux. If the installer proposal fails, check the actual
  device name in the installer's log/console.
- **Desktop pattern name** (`management.xml` only): assumes `gnome` + `x11`
  patterns exist in the Leap 16.0 offline repo. If the install fails on
  software selection, run `zypper patterns` against the ISO's repo and adjust
  the `<patterns>` list in `management.xml`.
- **OEMDRV not detected**: confirm the second DVD drive's ISO volume label is
  exactly `OEMDRV` (case-sensitive) and `autoinst.xml` is at its root, not in
  a subfolder - `01-build-oemdrv-isos.ps1` handles both automatically.
